# Fronk 0.3.0 release candidate

This candidate brings the head-first installer workflow, exact model verification,
measured placement and contributor documentation into one distributable project.
Use the same manager on each computer, choose its role and follow the head's
instructions. The terminal manager is the recommended path; the graphical manager
calls the same commands but is experimental.

This is the first public version. It is meant to be tried, inspected and improved;
bugs and inconsistencies on unfamiliar machines are expected. Configuration
reports, focused fixes and clearer instructions are welcome. See
[the author and project](../ABOUT.md) and [how to share a result](../SHARE.md).

The supported model is **Qwen3.8-Flash-Next-Q4.gguf**, identified by the size and
SHA-256 in [MODEL.md](../MODEL.md). The synthetic demo runs before model selection
or download. Existing files and external SSDs are supported. Nodes receive only
their neuron units. Weights are not included in the release.

## Ordinary runtime

The default Apple Silicon head retains ordinary MTP, complete expert sums and
the measured Metal RAM + SSD placement. Deep native verification, branch/wave
scheduling, alternative AVX2 ordering and ready-block SSD pipelining remain
separate experiments. See [Where to help](../IMPROVEMENTS.md) to work on them.

The historical mixed-cluster 15–16 range is documented with its workload and
fragment-counting method in [MEASUREMENTS.md](../MEASUREMENTS.md). This release
does not claim a new speedup or a general rate for other machines and prompts.

The release preparation exercised these paths on physical hardware:

|---|---|
| M4 Pro head, M1 Pro Metal node, Intel iMac AVX2 node and Linux Shuttle AVX2 node | Packaged installation, normal calibration, synthetic demo, complete 20-unit placement, missing-unit transfers, numerical check and finished chat responses |
| Exact model and extraction | Whole 177,280,286,720-byte GGUF SHA-256 verified; every byte of all 20 units independently checked against source tensor coordinates and all unit digests recomputed |
| Node lifecycle on the three node platforms | Isolated install, upgrade, keep-state uninstall, purge preserving unrelated GGUF files and reinstall |
| macOS node service | LaunchAgent install, authenticated readiness, stop/restart and uninstall using an isolated prefix |
| Linux node service | Debian 13 systemd user-service install, authenticated readiness, stop/restart, upgrade, keep-state uninstall, reinstall and purge; existing worker kept running on separate ports |
| Graphical head manager | Compact role/backend choices, three-node handoff, masked pairing code, synthetic demo, existing GGUF verification, start and web chat inspected on the M4 Pro |
| Terminal manager | Automated handoff/resume, missing peers, model/download gate, upgrade and uninstall checks |
| Core and backend contracts | Sanitizer suites, local cluster tests, Metal/NEON checks and the executable custom-backend example |
| Source backend modules | Two named example modules, installer choices, self-test gate, upgrade persistence, platform filtering, rollback after a failed self-test and uninstall/reinstall |
| Client API | Real model discovery, non-streaming completion, SSE with token usage, malformed-request rejection and a complete arithmetic-tool round trip on the physical cluster |
| Community report | On-demand hardware/allocation/timing export; allowlist tests exclude names, addresses, paths, secrets and conversation text |

The earlier packaged cluster comparison produced identical completed answers. Its
controls drifted and the placement changed, so it is a functional qualification,
not evidence of a throughput improvement. No fresh 177 GB network download was
repeated: the existing file was verified in full, and the installer download
gate and identity/error handling were tested separately.

A later fresh packaged run on 2026-11-05 reached 15.61 tok/s in the console's
short test, with all units and no deadline misses. Three API-counted short
responses measured 14.53–15.74 decode tok/s. [TEST_CLUSTER.md](../TEST_CLUSTER.md)
includes the actual allocation and screenshots. The normal web-chat capture
was slower and remains identified separately in the three-minute film.

The final source export and installer artifacts carry SHA-256 manifests. The
release's attached verification report identifies their exact hashes and the
checks repeated after the final edits. That report distinguishes the earlier
physical run from later source/package regression tests.

## Platform limits to retain in the release notes

- Apple Silicon is the qualified performance head. The Intel macOS/Linux Vulkan
  adapter has a device probe, but a fresh packaged end-to-end GPU head run is
  still needed for each supported GPU/driver combination.
- Linux manual and systemd user-service paths were tested on Debian 13. Other
  distributions and login/session policies still need their own checks.
- GUI inspection covers the head workflow. Automated terminal tests cover more
  failure and uninstall paths; they do not prove every native file dialog.
- Service lifecycle checks used isolated loopback ports. A fresh macOS user
  account still needs the complete LAN demo and generation check through the
  installed LaunchAgent; a Terminal-launched worker does not qualify that
  permission context.
- The managers are unsigned/not notarized. Follow the platform launch guidance
  in [INSTALL.md](../INSTALL.md); do not disable OS protections globally.
- GitHub CI is supplied for Linux and macOS. Its hosted results become available
  after the public repository runs the workflow.

For first use, start at [README.md](../../README.md). For a failure, keep the
error and use [TROUBLESHOOTING.md](../TROUBLESHOOTING.md). For publication and
requalification, follow [RELEASE.md](../RELEASE.md).
